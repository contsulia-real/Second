# CLI 钱包节点实现方案

2026-10-09 · 未确认的实现草案，以下命令与钱包能力尚未交付。完整仓库核对见 [project-review-2026-10-09.md](project-review-2026-10-09.md)。

## 第一版形态

提供独立的 `second-wallet` 程序，复用 Second 库的 NodeRuntime、身份、连接、认证公开状态同步、LegalTask 编码、签名、提交及任务查询能力。钱包以普通节点身份接入，默认不启用 Validator。它管理用户的钱包资料和原始请求，不默认复制完整私有网络状态，不维护第二份权威余额。

第一版采用单进程交互式 CLI：打开钱包后运行节点，命令在同一进程内执行，退出时关闭本进程的节点。暂不新增常驻后台钱包服务、IPC 控制端口或图形界面。初始化、导入和备份可以离线执行；账户和支付地址只有对应 LegalTask 成功提交后才能显示为已注册。

## 命令与用户流程

下列为拟议交互方式，不是当前可执行入口：

```text
second-wallet init ./alice --network ./network.json
second-wallet open ./alice

wallet> account create
wallet> address
wallet> balance
wallet> send pay_... 10
wallet> status <task-id>
wallet> history
wallet> exit

second-wallet backup ./alice ./alice-backup
```

`send` 展示付款账户、收款地址和数量，明确确认后生成唯一 TaskId。原始业务意图和签名请求在发往网络前持久化。超时、断连或程序重启后查询或精确重提同一请求，不另建任务补发。受理、准备、最终认证与成功提交分别显示；只有 `succeeded` 表示本次付款完成。余额未知、过期或查询失败时不显示为零，也不使用本地交易记录推算一个权威余额。

`history` 第一版记录这个钱包创建和保存的请求及查询结果，不承诺完整的全网收款历史。`backup` 保存钱包资料、签发材料及未完成请求；不复制 Validator 签票状态，不将钱包备份当作节点签名安全恢复凭据。备份含秘密时必须受限访问，拒绝覆盖已有目标。

## 分工与复用

- CLI 层处理输入、确认和结果显示。
- 钱包存储层保存账户与地址资料、配置和原始请求，采用原子写入和目录排他；不保存另一份可独立改变的余额账本。
- 钱包运行层组合既有普通节点、明确的可信网络参数和业务请求客户端；复用连接预算、身份验证和请求期限。
- Second 核心继续负责授权任务执行、最终性、持久化和公开/私有数据边界。钱包不会把业务保证金、服务商组织或商业仲裁塞进核心。

## 授权边界

第一版保持现有 AuthorizerSet 模型。钱包要取得网络认可的 LegalTask 签名：可以使用本地持有的受信任 Authorizer 材料，或导入按既有格式签好的请求。新生成一个节点密钥不会自动获得业务写权限。Authorizer 材料是签发者权限，不是账户私钥；界面、帮助和备份说明不得把它称为账户所有权证明，也不能保证其他受信任签发者无权操作该账户。

普通用户仅凭新生成的账户私钥控制资产、任意新签发者无需准入等能力，不是现有代码已经提供的事实。若以后要求这些能力，需要另行明确资产控制规则；本钱包草案不删除信任校验，也不静默新增账户密钥绑定。

## M0 私有账户快照查询（已实现）

`balance`、`assets`、地址和交易历史使用既有 AccountQuery。账户密钥签名绑定 QUIC channel binding、查询种类、游标、generation 和随机 nonce。请求结构与签名通过后才调用私有快照读取器；public-only 节点没有读取器，返回 unavailable，私有数据不进入 PublicStateStore。每一页都重新检查账户签名。固定端点证书及 QUIC 身份认证保留。

每条账户查询连接只承载一次完整查询。首请求必须 cursor=0、generation=None；后续请求必须依次推进游标并带首响应的 generation，同一账户、同一种类、同一连接。generation 仅标识投影来源的本地快照，不表示跨节点共识进度或时间。终页后服务端结束连接；中途断开、错误请求或重启后不能恢复原分页，只能用新连接从零重新查询。没有旧接口兼容层，内部协议版本仍为 1。

首请求从 StateStore.load_shared 的一个不可变、已验证快照派生查询投影。账户存在状态、余额、委员会版本和该查询种类的所有行都来自此快照。资产查询在一次 Currency 扫描中同时计数和收集地址；普通 balance 只计数，不下载或保存全部资产。地址或历史查询各扫描其相关集合一次。后续页只切片紧凑的类型化投影，不再加载或扫描状态。构建完成即释放快照引用；投影不会延长整份私有快照的生命周期。

投影是短期派生结果，不是第二份资产真值或余额账本。分页期间发生的业务提交、委员会变化或本地 BFT 元数据写入均不会混入既有投影。需要再次观察状态时发起新查询，不替换 generation 为集合摘要。

资源限制：

- 每页最多 128 行，每次枚举最多 100000 行；balance 的数值不受枚举行数限制。
- 每投影最多 16 MiB：按 Vec 实际容量、投影结构和历史行持有的 TaskId 字节计费，共享 TaskId 也保守计费。每进程最多 4 个构建中或保留中的投影，预留载荷上限合计 64 MiB；分配器元数据、既有共享快照缓存和网络帧不计入该载荷预算。额度在状态读取前取得，满额返回 busy，不排入等待队列。
- 总期限为首请求进入账户处理后的 30 秒，涵盖构建和分页；等待下一页最长 5 秒，QUIC keepalive 不续期。查询完成、断开、失败或过期即释放投影与额度。扫描每 4096 项检查取消及期限；已进入的同步快照磁盘读取不能强行中断，返回后先检查取消，不再构建结果。
- 超行数、超字节预算或分配失败返回 budget_exceeded，不发送截断资产清单。会话失效关闭连接；客户端明确失败并丢弃已收集的部分结果。
- 钱包与库的完整查询客户端共享页校验和拼接路径。完整结果至多 100000 行；固定格式地址、最长 128 字节 TaskId、有限页帧共同约束字符串内存。不会为普通余额查询额外枚举资产。

响应增加 total（该查询种类的总行数）。资产类型必须 total=balance；地址、历史的 total 是其行数，balance 仍从 owner 派生。客户端检查种类专属形状、元数据一致、解析后的严格顺序、跨页边界、游标、终页及数量；非末页必须满 128 行并指向下一页，零行只允许首次空结果。完整枚举数量必须等于 total，资产数量还必须等于 balance。查询失败不会输出部分结果为完整余额。

拒绝原因包括 unauthorized、unavailable、invalid_query、budget_exceeded、busy、session_expired；传输断开、截止期限、格式损坏及持久化读取错误也明确失败。钱包使用最多 3 次新连接尝试，每次都重新认证并从零读取，失败不返回零余额。

来源声明明确：这是经过会话认证的节点私有快照回答，仍信任回答节点。形状与数量自洽不能阻止恶意节点同时伪造清单、total 和 balance。它不提供 BFT 账户完整性证明、全网最新余额或线性化读取保证，也不实现 M1/M2。
